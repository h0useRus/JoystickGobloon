# Подсветка джойстиков и действие Light LED (0.5.0)

Цель 0.5.0: новое действие **Light LED** — у поддерживаемого джойстика зажечь указанный светодиод указанным
цветом (и режимом мигания). Первая итерация — только **VKB** (у пользователя Gladiator EVO R и EVO OT L).
Другие производители — потом, тем же слоем бэкендов (таблица внизу).

Ветка: `feature/0.5.0` от `dev`. Работа по сессиям, одна сессия — один крейт (CLAUDE.md).

## Протокол VKB (по pyvkb; подтвердить в сессии 0)

- HID **feature report `0x59`**, длина 129 байт (с байтом report id). Запись — `HidD_SetFeature`, чтение — `HidD_GetFeature`.
- Пакет записи: `59 A5 0A` · `CRC16` (LE) · `R R` (2 случайных байта) · `N` (число записей) · N записей по 4 байта ·
  нули до 129.
- CRC16: начальное `0xFFFF`, полином `0xA001` (отражённый, как Modbus), считается по первым `(N+1)*3` байтам
  блока `R R N записи…` («не спрашивайте почему» — pyvkb).
- Запись LED (4 байта): `id` · 3 байта (24 бита) — после перестановки байтов (`byteswap("3")`) упакованы по 3 бита:
  `color_mode, led_mode, b2, g2, r2, b1, g1, r1`.
  - `led_mode`: 0 выкл, 1 горит, 2 медленно мигает, 3 быстро, 4 очень быстро.
  - `color_mode`: 0 color1, 1 color2, 2 color1/2, 3 color2/1, 4 color1+2.
  - Цвет — **0..7 на канал** (8 уровней): `#RRGGBB` → `round(c / 255 * 7)`.
- Чтение (`GetFeature 0x59`): если первые 3 байта `59 A5 0A` — байт 7 = N, дальше N записей. Это только то,
  что было записано этой командой (или «тестом LED» в VKBDevCfg), а не LED-профиль из прошивки.
- **Запись временная**: действует до выключения/переподключения устройства, прошивку и настройки VKBDevCfg не
  меняет. Меняются **только перечисленные LED**, остальные ведут себя по профилю устройства.
- Команда **заменяет весь список**: чтобы поменять один LED, прочитать текущий список, заменить/добавить запись,
  записать список целиком. Максимум записей за раз: pyvkb — 12, плагин Gremlin — 4 (+ фиктивная).
- Ошибка чтения (плагин Gremlin): у последней записи при чтении портится `led_mode`, поэтому плагин дописывает
  фиктивный LED `99` в конец каждого списка. Повторяем это, пока сессия 0 не покажет обратное.
- Номера LED (Gladiator K/NXT): **0** — основание (одноцветный: синий/красный, яркость в канале R color1/color2),
  **10** — RGB на рукояти, **11** — хатка (красный, яркость в R). У EVO R: **10** — большой
  RGB на верху рукояти, **11** — маленький красный у хатки; LED 0 видимо не горит (основания с LED нет).
- Одноцветные LED: светятся по **первому** каналу (R) нужного цвета; цвет `#000` = не горит.

## Как это встроить

### Хранение в профиле: своё действие `light-led` (решено)

В XML пишется своё действие `<action type="light-led">`. Совместимость с Gremlin не нужна: кто пользуется
нашими новыми действиями, тот перешёл на Joystick Gobloon. Главное — читать профили Gremlin, скачанные из
интернета; дальше пользователь настраивает их в нашем интерфейсе. Предупреждений о несовместимости нет.
Обёртка в `description` и отдельный файл рядом с профилем — отклонены.

### Слои

| Слой | Что | Образец |
| --- | --- | --- |
| **gob-lighting** (новый крейт) | lib.rs: общие `Device` / `Led` / `Mode`, `match` по `Vendor`; hid.rs: общий HID (поиск, `GetFeature`/`SetFeature`); **каждый производитель — свой файл**, `vkb.rs`: report `0x59`, кодирование записи и пакета, CRC, слияние с текущим списком, фиктивный LED 99 | gob-hidhide (HID, SetupAPI/CfgMgr), pyvkb |
| **gob-input** | Для устройства DirectInput отдать путь HID (`DIPROP_GUIDANDPATH`): у VKB report `0x59` лежит в той же коллекции джойстика, путь совпадает с `gob_lighting::Device::path` (сравнивать без учёта регистра) | dinput.rs |
| **gob-core** | `ActionKind::LightLed { device, led, color, mode, trigger }`, `trigger` = `press` / `release` / `activate`, `NewAction::LightLed`; своё действие `light-led` | `PlaySound` в action.rs / edit.rs |
| **gob-gremlin** | `<action type="light-led">` ⇄ `LightLed`; round-trip-тест | — |
| **gob-engine** | `Node::LightLed`; `Output::light_led(device, led, color, mode)` по `trigger`: на нажатие, на отпускание или один раз при активации профиля (все `activate` сразу после старта); при остановке профиля LED не трогаем | `Node::PlaySound`, `Output::play_sound` |
| **Runner** | Отдельный поток `lighting`: HID-запросы не тормозят цикл движка; последняя команда на LED побеждает (схлопывать очередь) | media.rs |
| **joystick-gobloon** | Пункт «Light LED» в меню действий (иконка `LIGHTBULB`); редактор: устройство (подключённые с поддержкой LED), LED (имена для известных моделей + номер), цвет (палитра 8×8×8 с предпросмотром), режим (горит / мигает медленно / быстро / очень быстро / выкл), когда срабатывает (нажатие / отпускание / при активации профиля), кнопка «проверить» (зажечь сейчас, когда профиль не активен); лампочка на вкладке устройства с LED; i18n на 7 языков | редактор play-sound |

Если устройства нет или оно не поддерживается — действие **молча ничего не делает** (одна строка в лог при
активации профиля, без диалогов).

## Безопасность и проверка

- **Только реальное железо** пользователя; любая запись в устройство — **с его согласия**, сначала один LED, с
  возвратом в исходное (пустой список / прежний список). Чтение — без ограничений.
- Запись временная (до переподключения) — это проверить в сессии 0/1 первым делом: переподключить стик после
  записи и убедиться, что LED вернулись к профилю VKBDevCfg.
- HidHide: Joystick Gobloon в белом списке, поэтому скрытый VKB он открыть может. Отладочный exe тоже в списке;
  примеры gob-lighting HidHide скрывает — запускать их копией под именем `target\debug\examples\monitor.exe`.
- `SetFeature` идёт на открытый параллельно с DirectInput хэндл (`FILE_SHARE_READ | FILE_SHARE_WRITE`) — проверить,
  что опрос осей не сбивается.

## План работ (сессии)

### 0. Разведка (gob-lighting, только чтение)

- [x] Пример `led_probe`: все HID-коллекции VID `0x231D`. Итог: у EVO R (`pid 0200`, как NXT) и EVO OT L
      (`pid 3201`) одна коллекция Joystick `0001:0004`, feature report один — `0x59`, 129 байт. LED-report в той
      же коллекции, что опрашивает DirectInput: путь HID = путь из `DIPROP_GUIDANDPATH`, родитель не нужен.
- [x] `GetFeature 0x59` у обоих стиков до записи: `59 00 00 …` (не `59 A5 0A`) — пустой список.
- [x] Номера LED у EVO R: в VKBDevCfg (Global → External → LEDs) те же 0 / 10 / 11, что у NXT; на глаз — 10 и 11
      (см. «Номера LED» выше). EVO OT L не проверяли, ожидаем то же.

### 1. gob-lighting + бэкенд VKB

- [x] Крейт, модуль `vkb`: кодирование записи и пакета, CRC16 — юнит-тесты на эталонные байты из pyvkb

      файле (`vkb.rs`, потом `winwing.rs`, …): там его протокол/SDK, поиск устройств и запись; lib.rs — общие
      `Device` / `Led` / `Mode` и `match` по `Vendor`.
- [x] Слияние с текущим списком, фиктивный LED 99, возврат (`release` / `release_all`).
- [x] Пример `led_set <device> <led> <#RRGGBB> [mode]` / `led_set <device> clear [led]`.
- [x] Проверка `led_set` на железе (EVO R, прошивка 2.20C, с согласия пользователя, 2026-10-19):
      - LED 10 белый / зелёный, LED 11 красный — горят; несколько LED в одном списке работают; чтение обратно

## Открытые вопросы

1. ~~Хранение в профиле~~ — своё действие `light-led`, без совместимости с Gremlin.
2. ~~Нумерация LED у EVO~~ — 10 и 11, как у NXT.
3. ~~Возврат LED~~ — вернуть прошивочное поведение нельзя (убрать из списка не помогает, профиль VKBDevCfg
   прочитать нечем), и не нужно: состояние задаёт профиль. У действия три срабатывания: **нажатие**,
   **отпускание** и **при активации профиля** (постоянный цвет; ставится сразу после старта профиля). «Пока
   нажато» = два действия: цвет на нажатие + цвет на отпускание. При остановке профиля LED остаются как есть.
   Переподключение стика во время игры — редкость: после него профиль деактивируют и активируют снова, и
   действия «при активации» опять выставят нужные цвета.
4. Нужны ли color2 и режимы смешивания цветов (`color1/2`, `color1+2`) в первой итерации — предлагаю нет:
   один цвет + режим мигания.
