The idea

What a picture shows

"Button 17" says little; a hat on the top of your grip says a lot. A device picture is a photo or drawing of your controller with a mark on every control: a pad for each hat, a ring for a stick, a gauge for an axis and a round tag for each button. When you press a button, push a hat or move an axis, its mark lights up, so you see at once which control is which.

Where you see it

  • Input viewer: switch Picture on under a controller to see it next to its graphs, lit live.
  • Game bindings page, Controller tab: the picture with a card beside each control, listing the game actions it drives through your profile. Drag a card up, down or to the other side; where you put it is saved in the profile, so a profile you share shows the cards the same way. The magic wand puts them back. See Game bindings.

Get a picture

Download one

The program comes without pictures and fetches the one your controller needs. Open the Input viewer: a connected controller without a picture shows Download picture when there is one made for it. Click it and the picture appears a moment later; from then on it works offline. A controller that has none yet shows Add a picture instead (see Make your own).

The program recognizes a controller by its USB ids and the name it reports, so a stick renamed in its maker's configurator may not be found. Pictures come from the program's repository on GitHub: final releases take the list of the latest release, alpha builds the newest. Downloaded pictures go into your own devices folder, where you can change them like your own.

Make your own

1. The photo

A good picture makes the rest easy. Before you start:

  • Format: PNG with a transparent background is best, so the picture sits cleanly on the dark and the light theme. JPEG works too (it keeps its background). An SVG drawing is also fine and follows the theme's colors.
  • Size: about 750 pixels high and up to 1000 wide. The program shows every picture at the same height (about 620 pixels), so a larger one only makes the file bigger; a much smaller one looks soft.
  • View: the side that shows the most controls, usually a three-quarter view from the front and the thumb side. Every hat, button, switch and wheel should be visible; whatever is hidden behind the grip cannot be placed.
  • Crop: the whole device, with little empty space around it. No text, logos, badges or arrows over it.
  • Background: to remove a photo's background, any image editor with a background eraser does the job; on a plain white background a magic wand is enough.
  • Rights: your own photo is always fine. For a maker's product photo, keep to the maker's terms and put their credit in credit (see device.gob).

2. Add the picture

Connect the controller, open the Input viewer and click Add a picture under it. Give the device its Brand and Name, choose the picture file and keep the connected Controller selected: the new picture then belongs to that controller and shows up whenever it is connected. Create opens the picture for mapping.

A picture of a controller you already have opens for mapping with the pen above it (Edit mapping).

3. Place the controls

While mapping, the program listens to the controller. Press a button, push a hat or move an axis: its number appears in the top left corner of the picture. Drag it onto the spot where that control is. Then the next one, until every control has its place; a number dropped by mistake goes back with a right click.

  • Placed tags move by dragging them; click one to select it and rename it in the list on the right (the names show on the Controller tab's cards).
  • The list shows every placed control with the inputs it sends; the picture lights each one as you work the controller, so you can check them all at the end.
  • Done finishes. Every change is saved at once.

4. Hats, sticks and lines

  • Hats: many controllers send a hat as four or five buttons. Right-click the button in the middle of the hat and choose Make it a hat: the buttons around it go into its directions and the middle one becomes the push. Buttons dragged near a hat open a slot for each direction to drop onto.
  • Sticks: axes dragged near each other gather into one stick (X, Y and twist), drawn as a ring whose dot follows the stick.
  • Crowded spots: when controls sit too close to read, move one out of the way with a line to its place: Shift+drag it, or right-click it and choose Move out with a line. Drag the dot at the line's end to move the spot itself; Back on its spot undoes it.
  • Mistakes: Split it up takes a hat or stick apart again, Remove from the picture sends a control back to the corner.

Copy from the other hand

A left-hand stick usually has the controls of the right-hand one, mirrored. The copy button next to Done (Copy the controls from another device) takes every control of another picture, with Mirror left and right for the other hand's model. Then only move the tags that ended up a little off.

Share it

Export and import

The share button above a picture saves the picture with its controls as one .zip file. Others import it with the import button of the Input viewer; if they already have a mapping of the same device, the program asks before replacing it. Only pictures and the device's text files are taken from a shared file.

Add it to the program

A finished picture helps every owner of that controller. Send the exported .zip in a GitHub issue or on Discord, with the name your controller shows in Windows (Game Controllers, joy.cpl). If you know Git, add the folder under plugins/devices/<brand>/<device>/ in a pull request and run cargo run -p gob-devices --example device_index to update the list of pictures. Use only photos you took or are allowed to share.

The files

Where they live

Each picture is a folder of plain text files and images in the devices folder of the program's data folder: %APPDATA%\JoystickGobloon\devices on Windows, ~/.config/JoystickGobloon/devices on Linux, or next to the program for a portable copy with its own settings. Folders go by brand and device, like devices\vkb\gladiator-nxt-evo-r. The program notices changes made by hand and loads them again within a few seconds.

gladiator-nxt-evo-r/
  device.gob      the device, the controllers it fits, its pictures and controls
  inputs.gob      which button, axis or hat each control sends
  views/main.png  the picture

device.gob

The program writes this file while you map, and keeps comments and order when it changes it, so it is safe to edit by hand too:

id = "vkb-gladiator-nxt-evo-r"          # unique, lower case
name = "Gladiator NXT EVO (right)"
brand = "VKB"
credit = "Product images (c) VKB-Sim, used with permission"   # shown under the picture
version = "1"

[[match]]                 # a connected controller this picture is for
vid = 0x231D              # USB vendor id
name = "Gladiator EVO R"  # part of the name it reports (pid = 0x0200 also works)

[[view]]                  # a picture; a device may have several (grip, base)
id = "main"
name = "Stick"
image = "views/main.png"

[[control]]
id = "hat_1"
name = "Hat 1"
kind = "hat"              # button, trigger, hat, encoder, switch, lever, axis, stick
at = [419, 76]            # its spot, in pixels of the picture
side = "right"            # the side its card goes to on the Controller tab
# glyph = [520, 60]       # where it is drawn when moved out with a line
# parts = ["up", "right", "down", "left", "push"]   # a hat that clicks

Between two pictures that fit a controller equally well, the one whose name part names more of it wins, so "Gladiator EVO OT L" beats "Gladiator EVO". A second view needs its own picture in views/ and view = "<its id>" on the controls placed on it; the Input viewer then shows a tab for each view.

inputs.gob

Which input each control (and each part of it) sends, in the controller's default setup:

button_1 = "button:1"
axis_z = "axis:z"           # x, y, z, rx, ry, rz, slider, dial
hat_1 = "hat:1"             # a hat on a real POV hat: its four directions

[hat_2]                     # a hat made of buttons: one input per part
up = "button:11"
right = "button:12"
down = "button:13"
left = "button:14"
push = "button:15"

If your controller is set up differently from its picture (buttons renumbered in its configurator), map it again with Edit mapping. A picture that came with the program or was downloaded is copied into your devices folder the first time you change it, so your changes are never overwritten.
